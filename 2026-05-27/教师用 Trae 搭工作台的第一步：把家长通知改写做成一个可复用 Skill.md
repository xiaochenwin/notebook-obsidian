上一篇文章讲到，教师用 Trae 的下一步，不是继续堆提示词，而是搭一个自己的 AI 工作台。

写完以后，我反而更想补一句：

工作台这件事，千万不要一开始就做大。

很多人一听到工作台，脑子里马上会出现一个很完整的系统：

-   • 要有个人规则
    
-   • 要有项目规则
    
-   • 要有资料库
    
-   • 要有模板
    
-   • 要有 Skills
    
-   • 要有 Agent
    
-   • 还要接 MCP
    

这些当然都重要。

但如果一个老师刚开始用 Trae，就想一次性把所有东西搭全，大概率会很快卡住。

因为真正的问题不是目录不够完整，而是你还没有找到一个最值得沉淀的小任务。

所以我想直接从一个非常具体、也非常高频的教师场景开始：

`把学校通知改写成适合发给家长的版本。`

这件事几乎每个老师都遇到过。

学校发来一份活动通知、报名说明、材料收集要求、放假安排、讲座提醒。

原文往往很正式，也很完整，但不一定适合直接发给家长。

老师真正要做的，不是重新写一篇，而是把它改成：

-   • 家长能快速看懂
    
-   • 时间地点不能错
    
-   • 材料要求不能漏
    
-   • 语气要清楚、亲切、不过度行政化
    
-   • 最后最好还能提醒自己哪些信息需要复核
    

这就是一个很适合放进 Trae 工作台的任务。

因为它高频、重复、有固定流程，也有明确边界。

如果用一句话概括这一篇，我会这样说：

`教师搭 Trae 工作台，不要先追求完整，而要先把一个反复出现的小任务做顺。`

## 为什么先从家长通知改写开始

我之所以建议从“家长通知改写”开始，不是因为它最复杂。

恰恰相反，是因为它足够小。

它不像完整教学设计那样牵涉课标、教材、学情、活动、评价。

它也不像 Excel 成绩分析那样牵涉字段、口径、数据质量和统计解释。

它更像一个教师日常里很典型的小任务：

有一份原始材料。

有一个明确读者。

有一个稳定输出。

有一些不能乱动的关键信息。

这四件事一旦具备，就很适合拿来训练工作台。

比如一份原始通知里，通常有这些信息：

-   • 活动时间
    
-   • 活动地点
    
-   • 参与对象
    
-   • 报名截止时间
    
-   • 需要准备的材料
    
-   • 联系方式
    
-   • 注意事项
    

老师要做的不是让 AI 自由发挥，而是让它先把这些信息提出来，再转换成家长容易理解的表达。

这里最重要的不是“写得更漂亮”。

而是“稳定不出错”。

通知这种内容，看起来只是几段文字，但它有很强的边界。

时间不能乱改。

地点不能乱写。

费用不能自己猜。

学生信息不能外露。

学校没有写的承诺不能替学校补上。

这也是它特别适合做成 Skill 的原因。

因为 Skill 要沉淀的，不是某一句好看的提示词，而是一套处理这类任务时必须遵守的流程。

## 普通聊天为什么容易反复修改

很多老师第一次处理这类任务，会直接对 AI 说：

`帮我把这份通知改成适合发给家长的版本。`

这句话当然能用。

AI 也往往能写出一版看起来还可以的内容。

但你很快会发现，它未必知道你的默认规则。

它可能会把原本很重要的时间写得不够醒目。

它可能会把“请各班主任统计报名人数”改成“家长请自行报名”。

它可能会为了语气亲切，自己补出一些原文没有的解释。

它也可能没有在最后提醒你：这是一份对外发送内容，必须人工复核。

于是你只好继续补充：

-   • 时间地点不要改
    
-   • 报名方式按原文来
    
-   • 不要扩写没有依据的内容
    
-   • 语气再像老师一点
    
-   • 最后列出需要确认的信息
    

这就是之前说过的低效循环：

`你不是不会用 AI，而是在不断重复培训同一个助手。`

一次两次还好。

但如果这类通知每周都有，问题就很明显了。

同样的要求，你会一遍遍说。

同样的错误，你会一遍遍纠正。

同样的格式，你会一遍遍调。

这时候真正值得沉淀的，就不是这一次通知文本，而是“家长通知改写”这套方法。

## 先建一个最小教师工作台

如果只是为了跑通第一个 Skill，我建议工作台目录先保持很小。

不用一上来放很多资料。

可以先建成这样：

```
教师AI工作台/
├─ 00-项目规则.md
├─ 01-输入材料/
│  └─ 原始通知.md
├─ 02-输出模板/
│  └─ 家长通知模板.md
├─ 03-过往样例/
│  └─ 家长通知样例.md
├─ 04-skills/
│  └─ 家长通知改写
│	└─ SKILL.md
└─ 05-输出结果/
```

这个结构不复杂，但已经够用了。

因为它把一次通知改写需要的几个东西分开了：

-   • 项目规则：告诉 Trae 这个项目的基本边界
    
-   • 输入材料：放原始通知
    
-   • 输出模板：规定家长通知长什么样
    
-   • 过往样例：给 Trae 一个风格参考
    
-   • Skill：告诉 Trae 遇到这类任务按什么流程做
    
-   • 输出结果：保存改写后的版本
    

你会发现，这里没有任何神秘东西。

它本质上就是一个整理好的文件夹。

但这个文件夹一旦放进 Trae，意义就变了。

因为 Trae 不再只根据你当下那一句话工作。

它可以围绕一个稳定项目继续协作。

![[笔记同步助手/images/59d61bc4f3f2abfdadb73b6c542faa37_MD5.png]]

## 项目规则不用长，但边界要清楚

第一个文件，可以先写 `00-项目规则.md`。

我建议先不要写太长。

对于“家长通知改写”这个最小工作台来说，规则可以这样写：

```
# 教师家校沟通工作台规则

这个项目用于处理学校通知、活动说明、报名提醒、材料收集等家校沟通文本。

主要输出对象是家长。

输出要求：
- 表达清楚、简洁、亲切，避免过度行政化。
- 优先保留原通知中的时间、地点、对象、材料、截止时间、联系方式。
- 不自行改动事实信息，不补充原文没有依据的承诺。
- 涉及费用、学生隐私、成绩、评价、医疗健康、安全责任等内容时，必须标出复核提醒。
- 对外发送前，必须提醒教师人工确认最终措辞和关键信息。
```

这份规则解决的是方向问题。

它让 Trae 知道，这个项目不是随便写文案。

它处理的是家校沟通内容。

它面向的是家长。

它的重点不是写得花哨，而是准确、清楚、可复核。

有了项目规则，后面每次处理通知时，你就不用从头解释这些底线。

## 模板和样例比形容词更可靠

很多老师在让 AI 改通知时，会说：

`语气亲切一点。`

`格式清楚一点。`

`像我们平时发给家长的那种。`

这些话当然可以用。

但它们的问题是太抽象。

什么叫亲切？

什么叫清楚？

你们学校平时到底怎么写？

如果不给模板和样例，AI 只能猜。

所以第二步，我会建议放一个最简单的 `家长通知模板.md`。

比如：

```
# 家长通知模板

各位家长好：

【通知事项】
用一两句话说明这次通知的核心事项。

【时间地点】
- 时间：
- 地点：

【需要准备】
-

【家长需要配合】
-

【温馨提醒】
如有特殊情况，请及时与班主任联系。
```

再放一个 `家长通知样例.md`。

样例不用多，一两篇真实风格就够。

比如：

```
各位家长好：

本周五下午学校将组织四年级学生参加校内科学实践活动，请同学们按要求准备记录本和文具。

活动时间：本周五 14:00-16:00
活动地点：学校科学教室

请家长提醒孩子当天带好记录本、水杯，并穿着便于活动的服装。

如孩子当天身体不适或无法参加，请提前与班主任联系。
```

模板和样例的价值，是把抽象风格变成具体参照。

它们比“写得亲切一点”稳定得多。

当 Trae 能看到模板和样例，它就更容易知道：

-   • 开头怎么称呼
    
-   • 信息怎么分组
    
-   • 句子要多长
    
-   • 提醒怎么写
    
-   • 什么语气适合家长阅读
    

很多时候，AI 输出不稳定，不是因为它不懂你的形容词，而是因为它缺少参照物。

## 把家长通知改写流程写成 Skill

前面几步，已经有了项目规则、模板和样例。

接下来才进入真正的关键：把这类任务写成 Skill。

这里说的 Skill，你可以先把它理解成一份“写给 Trae 的任务流程说明”。

不同工具版本里的入口和形态可能不完全一样，但核心不变：

`把一类高频任务的处理步骤固定下来，让下次不用重新解释。`

比如 `04-skills/家长通知改写/SKILL.md` 可以这样写：

```
---
name: 家长通知改写
description: 当用户要求把学校通知、活动说明、报名提醒、材料收集要求改写成家长版通知时，按以下流程执行。
---
# 家长通知改写
## 1. 先提取关键信息
- 通知事项
- 时间
- 地点
- 参与对象
- 需要准备的材料
- 截止时间
- 联系方式
- 风险或注意事项

如果原文没有写清楚，不要自行补充，标为“需确认”。

## 2. 保留不可改动信息

以下内容不得自行改写事实：
- 日期、时间、地点
- 人员范围
- 报名方式
- 费用金额
- 材料清单
- 学校正式要求

## 3. 改写成家长易读版本

要求：
- 开头使用“各位家长好”
- 先说明核心事项
- 再列时间地点
- 再列需要准备和配合的事项
- 语气清楚、亲切、不过度口语化
- 避免行政公文腔

## 4. 输出教师复核清单

通知正文后，额外列出：
- 需要教师确认的信息
- 可能涉及隐私、费用、安全、健康、成绩、评价的风险点
- 建议发送前再次核对的内容

## 5. 不做的事
- 不编造原文没有的信息
- 不替学校作出承诺
- 不自动删除重要要求
- 不直接发布最终通知
```

这份 Skill 看起来不长，但它已经把一个模糊任务拆成了稳定流程。

它告诉 Trae：

先提取信息。

再保留边界。

再改写表达。

最后提醒复核。

这和一句“帮我改得适合家长看”不是一个层次。

一句提示词更像临时要求。

Skill 更像固定流程。

## 用一个真实通知跑一遍

假设你有一份原始通知：

```
各班主任：

学校拟于 5 月 12 日下午 14:30 在报告厅组织四年级学生参加“校园安全教育讲座”。请各班于 5 月 10 日 17:00 前完成参加学生名单统计，并提醒学生携带记录本和黑色签字笔。讲座期间请各班安排一名教师随班管理。因身体原因不适合参加集体活动的学生，请提前报德育处备案。
```

如果是普通聊天，你可能会说：

`帮我改成家长通知。`

但在这个工作台里，你可以这样提需求：

```
请使用 04-Skills/家长通知改写，
参考 02-输出模板/家长通知模板.md 和 03-过往样例/家长通知样例.md，
把 01-输入材料/原始通知.md 改写成适合发给四年级家长的通知。

要求：
- 保留时间、地点、材料和截止时间。
- 不补充原文没有的信息。
- 最后列出教师复核清单。
```

这时候，Trae 接到的就不是一句孤立请求。

它看到的是一个相对完整的工作环境。

它可以输出成这样：

```
各位家长好：

学校将于 5 月 12 日下午组织四年级学生参加“校园安全教育讲座”，请家长协助提醒孩子做好相关准备。

【时间地点】
- 时间：5 月 12 日下午 14:30
- 地点：学校报告厅

【需要准备】
- 记录本
- 黑色签字笔

【家长需要配合】
- 请提醒孩子按要求携带记录本和黑色签字笔。
- 如孩子因身体原因不适合参加集体活动，请提前告知班主任。

【温馨提醒】
学校需在 5 月 10 日 17:00 前完成参加学生名单统计，如有特殊情况，请及时与班主任联系。

---

教师复核清单：
- 请确认活动时间、地点是否仍为 5 月 12 日 14:30、学校报告厅。
- 请确认名单统计截止时间是否为 5 月 10 日 17:00。
- 请确认“不适合参加集体活动”的学生是否需要按学校要求报德育处备案。
- 正式发送前，请人工复核最终措辞。
```

这版内容不一定完美。

但它已经接近教师真正想要的工作方式：

正文给家长看。

复核清单给老师看。

关键信息没有被随意改动。

没有编造学校没有说的安排。

这就是可复用流程的价值。

## 复用价值不在这一次，而在下一次

如果只看这一次通知，你可能会觉得：

这不就是一段提示词也能做到吗？

确实。

一次任务，用提示词也能完成。

但工作台和 Skill 的价值，从来不只看一次。

真正的价值在下一次。

下周又来一份研学报名通知。

下个月又来一份体检提醒。

期末又来一份材料收集说明。

如果每次都重新说一遍规则，你还是在原地循环。

但如果已经有了项目规则、模板、样例和 Skill，你下次只需要替换原始通知，再说：

`按家长通知改写 Skill 处理这份通知。`

然后每次做完，再把好的版本放进过往样例。

如果这次发现 AI 容易漏掉“截止时间”，就把“截止时间必须单独提取”补进 Skill。

如果这次发现通知涉及费用，就把“费用必须原样保留并提醒复核”写得更明确。

如果这次发现家长反馈某种表达更清楚，就更新模板。

这时候，工作台就不是一次性搭出来的。

它是在真实任务里不断变稳的。

## 一个小任务跑顺后，再扩展第二个

我不建议教师一开始就把所有任务都做成 Skill。

更好的节奏是：

先选一个最痛、最频繁、最容易重复的任务。

把它跑顺。

再把流程留下来。

然后再做第二个。

比如“家长通知改写”跑顺以后，就可以继续做：

-   • 活动方案整理 Skill
    
-   • 教案初稿生成 Skill
    
-   • 学生评语润色 Skill
    
-   • 班级周总结 Skill
    
-   • PDF 材料提炼 Skill
    

这些任务表面不同，但方法是一样的。

都不是先追求 AI 一句话全做完。

而是先问：

-   • 输入材料是什么
    
-   • 输出结果给谁看
    
-   • 哪些信息必须保留
    
-   • 哪些地方必须人工复核
    
-   • 这套流程能不能留给下次
    

如果这些问题能回答清楚，Skill 就有了基础。

所以第六篇真正想讲的，不只是“怎么改写家长通知”。

它更想讲的是：

`教师的 AI 工作台，应该从一个可复用的小流程开始长出来。`

## 写在最后

Trae 已经不只是一个新工具了。

它开始指向一种更稳定的教师 AI 工作方式。

不要急着搭一个完整系统。

先从一个高频任务开始。

先把一次家长通知改写做顺。

再把做顺的流程写成 Skill。

再把模板和样例放进工作台。

再在后续任务里不断修正它。

这样做的好处是，它不会让老师一上来就背负一个很大的建设任务。

你只是在解决一个真实问题。

只是这一次，解决完以后，方法没有丢掉。

它被留下来了。

`教师用 Trae 搭工作台的第一步，不是先搭全，而是先把一个经常重复的小任务做成可复用流程。`

## 文末互动

如果你也在尝试把 Trae 放进教学、教研或班主任工作里，可以先不用想太大。

你可以先问自己：

`我最常重复、最想交给 AI 先处理的小任务是哪一个？`

是家长通知改写？

是活动方案整理？

是教案初稿？

是学生评语？

是班级周总结？

还是 PDF 材料提炼？

如果这个任务每次都差不多，但你每次都要重新解释，那它就很适合做成你的第一个 Skill。

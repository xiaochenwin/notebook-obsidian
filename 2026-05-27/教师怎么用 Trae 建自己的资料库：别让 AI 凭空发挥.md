上一篇文章里，我用“家长通知改写”做了一个很小的例子。

不是让 Trae 临时帮我们写一段通知，而是把这类高频任务整理成一个可以复用的 Skill。

这个思路很重要。

因为教师真正长期使用 AI，不应该每次都从零开始。

但其实还留下了一个问题：

如果只有 Skill，没有稳定资料，AI 仍然会猜。

比如你已经写好了“家长通知改写 Skill”。

它知道要先提取时间、地点、对象、材料和截止时间。

它也知道不能改动事实，最后要列出教师复核清单。

可是，如果它不知道你们学校平时通知的语气，不知道你们班家长阅读习惯，不知道你常用的通知模板，也不知道哪些表达在你这里不合适，那它还是只能根据通用经验写。

这就是很多老师会遇到的情况：

明明已经给了 AI 一个任务流程，输出还是“不太像我”。

不是完全错。

但不够贴合。

有时候像公文。

有时候像营销文案。

有时候又像一个陌生人替你给家长说话。

所以我想继续往工作台里补第二块：

`教师怎么用 Trae 建自己的资料库，让 AI 不再凭空发挥。`

`资料库不是堆文件，而是给 AI 建立稳定上下文。`

## 为什么 AI 写出来的东西经常“不像你”

很多老师用 AI 写材料时，会有一种很微妙的感受：

它写得并不差。

甚至有些句子看起来还挺顺。

但就是不像自己平时会发出去的东西。

比如你让它写家长通知，它可能这样写：

`亲爱的家长朋友们，让我们携手为孩子的成长保驾护航。`

这句话不能说错。

但如果你平时给家长发通知的风格是简洁、清楚、少煽情，那这句话就显得不合适。

你让它写教案，它可能把教学目标写得很完整。

但它未必知道你所在学校常用的教案结构。

你让它写班级周总结，它可能会把语气写得很宏大。

但它不知道你们班这一周到底发生了什么，也不知道哪些事情适合对家长说，哪些事情只适合自己内部记录。

这时候很多人会继续调整提示词：

-   • 语气自然一点
    
-   • 不要太空
    
-   • 像老师一点
    
-   • 更符合我们学校风格
    
-   • 再具体一点
    

这些要求当然有用。

但它们仍然有一个共同问题：

太抽象。

AI 不知道“像老师一点”在你这里到底是什么意思。

它也不知道“我们学校风格”长什么样。

如果没有参考材料，它只能用自己的通用理解来补。

这就是“凭空发挥”。

凭空发挥不一定会导致明显错误。

更常见的是一种轻微跑偏：

-   • 语气不贴合
    
-   • 格式不稳定
    
-   • 重点不突出
    
-   • 细节自己补
    
-   • 案例不够真实
    
-   • 和你过去的表达不一致
    

这些问题靠一句更长的提示词可以缓解，但很难彻底解决。

因为真正缺的不是形容词，而是上下文。

## 资料库不是资料越多越好

一说到资料库，很多人第一反应是：

那我是不是要把所有文件都放进去？

学校通知、教案、课件、班级记录、活动方案、学生情况、公众号文章、政策文件，全都扔到 Trae 项目里。

这样看起来很完整。

但实际使用时，反而可能更乱。

因为 AI 并不是看到文件越多，输出就越稳定。

如果资料没有分类，没有说明，没有边界，它也会不知道该参考哪一份。

比如你把三年前的通知样例、今年的新通知模板、另一个年级的活动方案、别的学校的公众号文章放在一起。

当你让 Trae 写一份新通知时，它可能会混用风格。

它可能参考了旧格式。

也可能把别的年级要求误当成当前要求。

甚至会把只适合内部沟通的说法，写进对外通知里。

所以资料库的关键，不是“多”。

而是“清楚”。

一个好的教师资料库，至少要让 Trae 看明白三件事：

-   • 这类资料是什么
    
-   • 什么时候可以参考
    
-   • 哪些内容不能直接照搬
    

如果这三件事说不清，资料越多，AI 越容易乱引用。

所以我更建议教师从一个小资料库开始。

不用一上来整理全部工作。

先围绕一个高频任务建资料。

比如前面讲的“家长通知改写”，就先建一个家校沟通资料库。

等这个小资料库跑顺，再扩展到教案资料库、班主任资料库、公众号文章资料库。

工作台不是一次性搭满的。

它应该是在真实任务里慢慢变厚的。

## 教师资料库应该放什么

如果从教师日常工作看，我会把资料库先分成五类。

第一类，是学校要求。

比如：

-   • 学校通知常用格式
    
-   • 活动报名要求
    
-   • 安全提醒口径
    
-   • 家校沟通规范
    
-   • 教案格式要求
    
-   • 作业设计要求
    
-   • 公众号或宣传稿要求
    

这类资料的作用，是告诉 AI：

哪些内容不能随便改。

哪些表达需要符合学校口径。

哪些地方必须保守处理。

第二类，是班级背景。

比如：

-   • 年级和班级基本情况
    
-   • 本学期重点工作
    
-   • 班级常用称呼
    
-   • 家长沟通习惯
    
-   • 班级活动记录
    
-   • 一些不涉及隐私的共性观察
    

这类资料的作用，是让 AI 不要写得像面对一个完全陌生的班级。

但这里要特别注意：

学生个人隐私、健康信息、家庭情况、成绩评价等敏感内容，不应该随便放进资料库。

如果确实需要处理，也应该先脱敏，或者只保留概括性信息。

第三类，是学科资料。

比如：

-   • 课程标准摘录
    
-   • 教材单元说明
    
-   • 常用教学目标写法
    
-   • 课堂活动案例
    
-   • 作业设计样例
    
-   • 评价方式参考
    

这类资料主要服务教学设计。

它能让 AI 生成教案时不至于完全凭通用知识发挥。

但这里也有一个边界：

AI 可以辅助整理和生成初稿，但教学判断仍然要由教师把关。

第四类，是模板和样例。

比如：

-   • 家长通知模板
    
-   • 教案模板
    
-   • 活动方案模板
    
-   • 周总结模板
    
-   • 学生评语样例
    
-   • 公众号文章结构样例
    

模板解决“输出长什么样”。

样例解决“风格像什么”。

这两类资料往往比很多抽象提示词更可靠。

因为它们把风格变成了可参考的文本。

第五类，是临时材料。

比如：

-   • 本周学校通知
    
-   • 本次活动安排
    
-   • 当前要处理的 PDF
    
-   • 本节课教材片段
    
-   • 本次会议纪要
    
-   • 本次成绩表说明
    

临时材料不是长期规则。

它只服务当前任务。

任务结束后，可以把结果保存下来，但不一定要把所有临时材料都永久留在资料库里。

否则资料库会越来越乱。

![[笔记同步助手/images/f14f49548e2559714fc174a3ee84edea_MD5.png]]

## 长期资料和临时资料要分开

这是很多人搭资料库时最容易忽略的一点。

不是所有资料都应该长期保留。

我建议把资料分成两种：

`长期资料` 和 `临时资料`。

长期资料，是会反复影响输出的材料。

比如：

-   • 学校通知格式
    
-   • 家长通知模板
    
-   • 教案模板
    
-   • 公众号文章风格说明
    
-   • 常用表达边界
    
-   • 已经验证过的优秀样例
    

这些资料适合长期放在工作台里。

因为它们代表你的稳定规则、稳定风格和稳定方法。

临时资料，是只服务某一次任务的材料。

比如：

-   • 今天刚收到的一份活动通知
    
-   • 本周班级情况记录
    
-   • 这次讲座的报名名单
    
-   • 某节课要处理的教材片段
    
-   • 一份临时会议纪要
    

这些资料不一定适合长期放进资料库。

用完之后，最好放到任务记录或归档目录里。

如果其中有通用价值，再整理成模板、样例或规则。

这样做的好处是，资料库不会被临时文件淹没。

Trae 也更容易知道：

哪些东西是长期参考。

哪些东西只是这一次要处理。

一个简单的目录可以这样设计：

```
教师AI工作台/
├─ 00-项目规则.md
├─ 01-长期资料库/
│  ├─ 学校要求/
│  ├─ 班级背景/
│  ├─ 学科资料/
│  ├─ 输出模板/
│  └─ 过往样例/
├─ 02-临时输入/
├─ 03-Skills/
├─ 04-任务记录/
└─ 05-输出结果/
```

这个结构不复杂。

但它解决了一个很重要的问题：

`不要让长期上下文和临时输入混在一起。`

长期资料负责稳定。

临时资料负责当前。

二者分开，AI 才不容易把“这一次的特殊情况”误当成“以后都要遵守的规则”。

## 如何给资料分类：学校、班级、学科、模板、案例

如果只给一个最小可行版本，我会建议教师先用五个文件夹。

```
01-长期资料库/
├─ 学校要求/
├─ 班级背景/
├─ 学科资料/
├─ 输出模板/
└─ 过往样例/
```

这五类已经能覆盖大多数教师 AI 工作流。

`学校要求` 放那些必须遵守的外部规范。

比如通知格式、活动要求、教案检查标准、宣传稿口径。

这里的资料优先级应该比较高。

如果它和 AI 的自由发挥冲突，应以学校要求为准。

`班级背景` 放那些帮助 AI 理解对象的材料。

比如年级、班级整体特点、家长沟通习惯、本学期重点事项。

但这部分一定要注意脱敏。

不要把学生姓名、身份证号、家庭情况、健康信息、详细成绩等敏感内容长期放进去。

`学科资料` 放教学设计相关内容。

比如课标摘录、单元目标、教材结构、活动案例、作业样例。

这部分资料越清楚，AI 生成教学设计初稿时越不容易空泛。

`输出模板` 放各种结果的固定样式。

比如：

-   • 家长通知模板
    
-   • 教案模板
    
-   • 活动方案模板
    
-   • 班级周总结模板
    
-   • 学生评语模板
    
-   • 公众号文章模板
    

模板解决的是“长什么样”。

如果没有模板，AI 每次都会自己设计格式。

`过往样例` 放已经验证过的好结果。

比如过去发过的通知、改得比较顺的教案、质量比较好的活动方案、读者反馈较好的公众号文章。

样例解决的是“像什么”。

如果模板是骨架，样例就是语气和颗粒度。

这里有一个小建议：

每个资料文件开头，最好写一两句说明。

比如：

```
# 家长通知样例说明

这些样例用于参考家校沟通的语气和格式。
可以参考称呼、分段和提醒方式，但不得照搬具体时间、地点和活动安排。
```

这两句话很重要。

它告诉 Trae 这份资料应该怎么用。

否则 AI 看到样例，有时会把里面的具体内容也当成可以复用的信息。

资料库不是只存文件。

资料库还要告诉 AI：

`这些文件应该如何被参考。`

## 如何让 Trae 在项目里引用这些资料

资料库建好以后，不代表 AI 每次都会自动用对。

你还需要在提需求时，把引用关系说清楚。

比如不要只说：

`帮我写一份家长通知。`

更稳定的说法是：

```
请参考：
- 01-长期资料库/学校要求/家校沟通规范.md
- 01-长期资料库/输出模板/家长通知模板.md
- 01-长期资料库/过往样例/家长通知样例.md

处理：
- 02-临时输入/本周安全教育讲座通知.md

请输出：
- 一版适合发给四年级家长的通知
- 一份教师复核清单
```

这段话看起来比一句提示词长。

但它其实更省事。

因为它把“参考什么、处理什么、输出什么”说清楚了。

Trae 在项目里协作时，最怕的不是任务复杂。

最怕的是上下文混乱。

你给它十个文件，却不告诉它哪个是规则、哪个是样例、哪个是临时输入，它就只能猜。

所以我建议每次任务都尽量说清四件事：

-   • 参考资料
    
-   • 当前输入
    
-   • 输出形式
    
-   • 不得越过的边界
    

如果是之前的 Skill，也可以组合起来：

```
请使用 03-Skills/家长通知改写

长期参考：
- 01-长期资料库/学校要求/家校沟通规范.md
- 01-长期资料库/输出模板/家长通知模板.md
- 01-长期资料库/过往样例/家长通知样例.md

本次输入：
- 02-临时输入/安全教育讲座原始通知.md

输出到：
- 05-输出结果/安全教育讲座家长通知.md
```

这样一来，Skill 负责流程。

资料库负责依据。

临时输入负责当前内容。

输出目录负责结果沉淀。

这就是教师工作台逐渐稳定起来的方式。

## 一个家长通知资料库示例

继续沿用第六篇的场景。

如果要把“家长通知改写”真正做稳，可以先建一个很小的家校沟通资料库。

不用复杂。

只要能覆盖常见通知就够。

```
01-长期资料库/
├─ 学校要求/
│  └─ 家校沟通规范.md
├─ 输出模板/
│  └─ 家长通知模板.md
└─ 过往样例/
   ├─ 活动通知样例.md
   ├─ 材料收集通知样例.md
   └─ 安全提醒通知样例.md
```

`家校沟通规范.md` 可以写：

```
# 家校沟通规范

面向家长的通知应表达清楚、语气平和、信息完整。

必须保留原始通知中的时间、地点、对象、材料、截止时间、联系方式。

不得自行添加学校没有明确说明的承诺、解释、费用安排或活动变更。

涉及安全、健康、费用、学生隐私、成绩评价等内容时，必须提醒教师人工复核。
```

`家长通知模板.md` 可以写：

```
# 家长通知模板

各位家长好：

【通知事项】

【时间地点】
- 时间：
- 地点：

【需要准备】

【家长需要配合】

【温馨提醒】
```

`活动通知样例.md` 则放一两篇你已经确认过的真实风格样例。

但样例开头要写清楚：

```
本文件仅用于参考表达风格和分段方式。
不得照搬其中的活动时间、地点、对象和材料要求。
```

这样，下一次处理通知时，Trae 就不再只靠一句“语气亲切一点”来猜。

它可以看到规范、模板和样例。

它知道哪些信息要保留。

知道通知大概怎么分段。

也知道样例只能参考风格，不能照搬事实。

这就是资料库的价值。

不是让 AI 变成万能。

而是让它少猜。

## 一个教学设计资料库示例

再看教学设计。

很多老师让 AI 写教案时，会直接说：

`帮我写一份四年级语文《猫》的教案。`

AI 当然能写。

但如果不给资料，它很容易写得很泛。

因为它不知道你具体使用的教材版本，不知道学校教案格式，不知道这节课是一课时还是两课时，也不知道你班学生当前基础。

如果想让 Trae 更稳定地辅助教学设计，可以建一个教学设计资料库。

比如：

```
01-长期资料库/
├─ 学校要求/
│  └─ 教案格式要求.md
├─ 学科资料/
│  ├─ 语文课程标准摘录.md
│  ├─ 四年级下册单元目标.md
│  └─ 常用课堂活动案例.md
├─ 输出模板/
│  └─ 语文教案模板.md
└─ 过往样例/
   ├─ 阅读课教案样例.md
   └─ 习作课教案样例.md
```

使用时，可以这样说：

```
请参考：
- 学校要求/教案格式要求.md
- 学科资料/四年级下册单元目标.md
- 输出模板/语文教案模板.md
- 过往样例/阅读课教案样例.md

基于：
- 02-临时输入/本课教材内容.md
- 02-临时输入/本班学情说明.md

请生成一份教案初稿。

要求：
- 不编造教材页码和课标原文。
- 教学目标要能对应课堂活动。
- 最后列出需要教师人工判断和补充的部分。
```

这和直接说“帮我写教案”差别很大。

后者让 AI 自己猜依据。

前者把依据摆在它面前。

当然，即使这样，AI 生成的也只是初稿。

教师仍然要判断：

-   • 目标是否适合学生
    
-   • 活动是否真的可执行
    
-   • 提问是否有层次
    
-   • 时间安排是否合理
    
-   • 评价方式是否真实有效
    

资料库不是替代专业判断。

它只是让 AI 的初稿更接近真实工作现场。

## 资料库越清楚，Skill 越好用

我们已经把“家长通知改写”做成了 Skill。

但现在你应该能看到，Skill 和资料库其实是两件互相配合的事。

Skill 解决的是流程。

资料库解决的是依据。

如果只有 Skill，没有资料，AI 知道步骤，却不知道参考什么。

如果只有资料，没有 Skill，AI 看到材料，却不知道该按什么顺序处理。

这两者合在一起，才会变成一个更稳定的工作台。

比如处理家长通知：

-   • Skill 告诉 Trae：先提取信息，再保留边界，再改写表达，再输出复核清单。
    
-   • 资料库告诉 Trae：学校规范是什么，通知模板长什么样，过往样例是什么语气。
    
-   • 临时输入告诉 Trae：这一次具体要处理哪份通知。
    

这时候 Trae 输出的稳定性就会明显提升。

它不是突然“更聪明”了。

而是它能看的上下文更清楚了。

很多时候，教师用 AI 的关键不是让模型发挥更多。

恰恰相反，是减少它自由发挥的空间。

该参考什么，就明确给它。

该按什么流程做，就写成 Skill。

哪些地方不能动，就写进规则。

哪些结果必须人工复核，就放在输出要求里。

这才是可控的 AI 工作流。

## 不要把敏感信息随便放进资料库

讲教师资料库，必须单独说隐私和边界。

因为教师工作里有很多敏感信息。

学生姓名、成绩、家庭情况、健康情况、心理状态、处分记录、经济情况、联系方式，这些都不是普通素材。

不能因为 AI 能处理文本，就把它们随手放进长期资料库。

我的建议是：

能不放个人敏感信息，就不放。

能用概括性描述，就不要用具体身份。

能脱敏，就先脱敏。

比如不要写：

`张三最近三次数学测试分别是 62、58、61，家长工作忙，平时监管较少。`

可以改成：

`某学生近期数学基础题得分不稳定，家庭督促条件有限。需要生成沟通建议时，避免指责性表达。`

如果要处理成绩表、学生评价、家校沟通记录，最好把它们放在临时输入里。

任务完成后，只保留脱敏后的方法、模板或总结。

不要把原始敏感材料长期沉淀进资料库。

这里可以给工作台加一条规则：

```
涉及学生个人信息、成绩、健康、家庭、评价等敏感内容时：
- 优先使用脱敏描述。
- 不把原始敏感材料长期放入资料库。
- 输出前必须提醒教师人工复核。
- 不生成可能伤害学生或造成标签化的判断。
```

这不是形式主义。

这是教师使用 AI 的底线。

AI 工作台越往真实工作里走，越要重视边界。

否则资料库越完整，风险也越大。

## 每次任务结束后，只沉淀有价值的部分

资料库不是一开始建完就不动。

它应该跟着真实任务更新。

但更新也不能什么都往里塞。

我建议每次任务结束后，只问三个问题：

第一，这次有没有新的规则需要留下？

比如这次改写通知时发现，凡是涉及报名截止时间，都必须在正文里单独列出。

那就把它补进 `家校沟通规范.md` 或 Skill。

第二，这次有没有新的模板可以留下？

比如这次生成的“活动通知模板”特别清楚。

那就把空白模板整理出来，放进 `输出模板`。

第三，这次有没有好的样例值得留下？

比如这次通知语气、分段和提醒都很合适。

那就删掉具体时间、地点和敏感信息，只保留可参考的样例，放进 `过往样例`。

这样资料库会越来越有用。

它增长的不是文件数量。

而是可复用的经验。

我不建议把每一次原始输入都永久留在资料库里。

那样很快会变成另一个杂乱文件夹。

更好的做法是：

原始材料进临时输入。

输出结果进任务记录。

通用经验再沉淀到长期资料库。

这个动作看起来小，但它会让工作台逐渐成熟。

## 写在最后

教师用 AI，不能只靠临时聊天。

也不能只靠越来越长的提示词。

如果你希望 AI 的输出越来越稳定，就要把它需要参考的东西整理出来。

学校要求是什么。

班级背景是什么。

学科资料在哪里。

输出模板长什么样。

过往好样例有哪些。

哪些材料只是这一次临时使用。

哪些信息不能长期保存。

这些东西一旦清楚，Trae 就不需要每次都凭空发挥。

它会在你的规则、资料、模板和 Skill 里工作。

当然，这并不意味着 AI 会替你完成所有判断。

恰恰相反。

资料库建得越清楚，教师越容易把重复性的整理、改写、初稿生成交给 AI，把真正需要专业判断的地方留给自己。

如果用一句话总结这篇文章，我会这样说：

`教师资料库不是把文件堆给 AI，而是把稳定上下文整理给 AI。`

资料越清楚，AI 越少乱猜。

上下文越稳定，输出越接近真实工作。

## 文末互动

如果你已经开始用 Trae 搭自己的教师工作台，可以先不用整理所有资料。

先从一个小资料库开始。

比如：

`家长通知资料库`

或者：

`语文教案资料库`

也可以是：

`班主任周总结资料库`

你可以先放三样东西：

-   • 一个规则文件
    
-   • 一个输出模板
    
-   • 两三个过往样例
    

然后下一次使用 Trae 时，不要只说“帮我写一份”。

试着告诉它：

`参考哪些资料，处理哪份输入，输出成什么形式，哪些地方必须复核。`

这就是资料库真正开始发挥作用的时候。

下一篇如果继续这个系列，我会把工作台再往真实场景里推进一步：

`用 Trae 做班主任工作流：通知、总结、评语、家校沟通一次串起来。`

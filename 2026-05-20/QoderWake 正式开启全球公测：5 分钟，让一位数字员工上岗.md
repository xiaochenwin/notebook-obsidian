520 这天，给团队介绍一位新同事。

让一位 QoderWake 数字员工上岗，从打开应用到他开始接手第一个任务，大概五分钟。

今天起，QoderWake 开启全球公测，首发 Mac 版。访问 qoder.com/qoderwake 下载，安装即用。

## 一、挑一位入职

公测开放六个经过系统性训练的内置岗位，每一位都在 Qoder 团队的真实业务里磨过。

  

-   **后端工程师：**专注 API 开发、数据建模、服务集成和性能优化，按 Spec 增量交付并跑测试验证，让团队每周 PR 数量翻倍。
    
-   **前端开发工程师：**把设计稿翻译成组件，做视觉打磨、响应式适配、无障碍优化和性能调优，把界面还原从 1 个工作日压到 1 小时。
    
-   **测试工程师：**面向命令行工具和 Web 产品做测试计划、端到端测试、缺陷复现和基于证据的报告。不修代码、不跑单测，专做质量保障。
    
-   **产品经理：** PRD 生成、用户反馈分析、竞品研究和发布沟通，把从需求到文档的周期从小时级压到分钟级。
    
-   **数据分析师：**先框定问题和指标口径，通过三方数据源（如钉钉文档/表格的 MCP） 拉数据做诊断，输出带市场背景和证据的建议。
    
-   **内容运营专员：**从账号定位、热点洞察、内容日历到平台内容创作、视觉素材、品牌合规，全链条覆盖。外发前先经人工确认。人来决策，数字员工来执行。
    

![](https://relay-1.bijitongbu.site/p/a45e2f030336ec5e97ec1c4876953980.png)

> 新建数字员工（Waker） 弹窗。挑一个员工卡片，填写名字、头像和岗位简介，下方"保存并启用"按钮一点，他就入职了。

  

六位不够用？自定义员工支持设定名字、头像、核心职责、工作风格、工作流、技能和工具权限，几分钟就能上线一位专属于你团队的数字员工。

## 二、给他身份

选完员工角色，他立刻拿到一个身份。

这个身份不是会话级的。和聊完就忘的临时 Agent 不同，他作为一位数字员工长期在岗：记忆、技能、任务历史都持续积累，并随着工作不断进化。

他做出的每一份代码、PR、文档、报告都自动署上他的名字，谁写的、什么时候写的、跑了哪些验证，全部可追溯。数字员工首页能看到他的“履历”：入职天数、任务数、项目数，加上一张按日期铺开的工作热力图，一眼看出他这周忙不忙、上次活跃在哪天。

这部分不需要你做任何配置，保存角色那一刻就完成了。

## 三、安排他的“工位”

QoderWake 数字员工不被任何一台机器绑定。想让他 7×24 在岗，推荐部署在一台常驻运行的本地机器（比如 Mac Mini），你下班关电脑也不会把他打断。

他也长在团队的协作工具上。通过 IM Channel 把他拉进钉钉群，和真人组员一样，被 @ 就接活。通过 MCP 连接器接入团队已有的内部文档、知识库和业务系统，他读得了那份只在内网开放的 Wiki，也调得了你那个内部 API。

N 个真人和 M 个数字员工共享同一个项目空间，分工和上下文不需要重新交接。一个 4 人混编小队（1 位真人产品经理 + 1 位数字前端 + 1 位数字后端 + 1 位数字测试）能在同一个项目下跑完一个完整迭代。

## 四、划好边界，安全可控

安全可控是 QoderWake 产品在生产环境可用的前提。把生产环境的钥匙交给他之前，要先告诉他哪些事不能干。

每位数字员工都自带一个权限中心，四个维度把防护拆成工具防护、文件防护、内置工具、模型安全，每一类下面都是命过名、有严重程度、可独立开关的规则。

![](https://relay-1.bijitongbu.site/p/15aa5d5d4d4ad76121019831e34e90d8.png)

「工具防护」拦截命令注入和资源滥用，破坏性命令默认拦截，命中高危规则先请你授权；动文件前先备份，按目录设白黑名单；内置工具（代码搜索、终端、浏览器等）逐项可开关；模型对外输出经过独立护栏。能力交给模型和工具，边界由权限中心兜底。

## 五、告诉他怎么接活

接活方式有几种：

-   事件触发：通过配置自动任务的多种异步事件（ 如 Github Webhook）。有 Issue 被提交，webhook 自动把任务派给他。
    
-   周期性任务：通过配置自动任务，周期性的活他自己按时跑。
    
-   对话任务：打开对话框直接跟他说，临时的活随时派。
    
-   IM Channel：在 IM 里 @ 他，和派活给真人组员一样。
    

![](https://relay-1.bijitongbu.site/p/2b55e644f5d7192147cfddceaa1c5847.png)

> 自动任务配置页。绑定好项目，触发方式选“事件 / 由 Git 仓库事件触发”。换成“定时”就是定时任务视图。

### 然后他就上岗了

人下班了，数字员工还在岗。

GitHub 有 Issue 被提交，webhook 自动触发他开始干活。每个任务跑完都留下一份结构化的交付摘要：改了什么、跑了什么验证（Typecheck / Test / Build）、识别了哪些风险、PR 链接、推荐的 follow-up。你不需要打开 IDE，不需要拼凑现场。

![](https://relay-1.bijitongbu.site/p/b03ec8f52c090625f05341791308bfff.png)

> 一次自动任务跑完的样子。Delivery Summary 含 What changed / Verification results / Resolved risks / PR status / Follow-up。Typecheck、Test、Build 三项验证都标了具体输出；PR 链接直接可点。右侧是这位数字员工 Alex 的历史任务列表。

  

跑过的活会沉淀在他的 Waker 详情页里：一张工作热力图、一份记忆与规则清单、一份持续生长的技能库。每一次执行都是经验，第 1 天是基线，第 7 天就是你团队的资深专家。

![](https://relay-1.bijitongbu.site/p/7062b419df4115885fd9c460639562c3.png)

### 只需更多角色，便带来更多生产力

除了软件开发类角色，自定义角色能覆盖更多岗位。

比如自定义一位“产品分析员 Lindy”，她接到"做一份数字员工市场调研报告"之后，会自己把任务拆成五个阶段：范围与数据集、Porter Five Forces / PESTLE / SWOT、可视化图表、LaTeX 排版、PDF 编译，从定义范围、竞品分析、可视化图表到最终输出 PDF，一项一项跑完。

![](https://relay-1.bijitongbu.site/p/88dc6ff48ec3bfb49c187c4236303c88.png)

> 产品分析员 Lindy 的对话页。深度思考、加载技能、列出待办事项，从“定义范围”到“编译 PDF 并送审”，整张计划在你按下回车后自动展开。

### Harness-First架构

每一个数字员工任务完成的背后，都离不开 QoderWake 背后的驾驭工程（Harness Engineering）。

QoderWake 的驾驭工程实现了解耦编排、任务循环、上下文工程、反馈验证、状态持久化、崩溃恢复、完全护栏等业界共识技术能力。除此之外，还有两个核心能力：

  

-   **执行即经验**——每一次任务结果都被结构化沉淀，进入这位 Waker 的记忆和技能
    
-   **经验到能力**——足够多的记忆与技能在 Anti-Rot Governance（防腐治理）下被去重、去冲突、去过时，避免他越学越乱。
    

  

1 天起步、7 天变专家。第 1 天的基线到第7天的团队专家，在一个个实际生产任务中“长出来”，这是在持续进化。

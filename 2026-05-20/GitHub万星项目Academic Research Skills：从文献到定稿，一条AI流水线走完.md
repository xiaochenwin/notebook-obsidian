最近一两年，我身边搞科研的人——不管是刚开始带学生的青椒，还是正被论文折磨的博士生——越来越多人在用AI辅助学术写作。

但用着用着，问题也暴露得很集中。

一个做社会学的朋友跟我说，她用某通用AI工具整理了一章文献综述，交上去被导师打回来，因为引用的十几篇文献里有将近一半查不到原文。标题、作者、期刊看起来都对，但数据库里就是搜不出来。

另一个做传播学的博士生更头疼：AI帮他写了三个版本的方法论部分，读起来都"像那么回事"，但仔细一看，每个版本对同一个研究方法的定义都不一样。

不是AI没用。是把AI用错了位置。

你去问身边那些用AI写出过好论文的人，他们几乎从来不让AI直接"替"他们写。他们让AI做的事情更底层、更琐碎——查引文是不是真的、格式是不是统一、论证链条有没有断。

而这个思路，在一个GitHub开源项目里被做到了目前为止最系统化的程度。

​

## Academic Research Skills：一个不帮你写论文、专帮你守住底线的系统

这个项目叫 **Academic Research Skills**，简称 ARS。

GitHub 上搜 Imbad0202/academic-research-skills 就能找到，一万多颗星，台湾研究者吳政宜开发的。

它本质上是给 Claude Code 做的一套插件。Claude Code 你可以理解成一个运行在终端里的 AI 编程和研究助手——和你在浏览器里用的 ChatGPT 或者 Claude 不一样，它是通过命令行驱动的。

ARS 挂载到 Claude Code 上之后，就变成了四套专门的学术技能模块，覆盖了从文献研究、论文写作、同行评审到投前检查的全流程。每一套模块背后都是多个 AI 智能体在协同工作。

我读完整个项目的设计文档之后，最大的感受是：这个作者不是在做一个"帮你写论文"的工具，而是在设计一套防止AI搞砸你学术的系统。

这是两种完全不同的产品思路。

前者你得到一篇看起来还行、仔细读全是窟窿的论文。后者你得到的是一篇你真正理解、能答辩、能负责的论文。

## 四个模块，一套完整的学术流水线

ARS 的核心是这四个技能模块。每一块单独拿出来都能用，串在一起就是一条从选题到发表的完整流水线。

​

### 第一关：Deep Research——13个智能体协同梳理文献

做文献综述最折磨人的地方，不是读，是"不知道还有什么该读"。

你搜了几个关键词，筛了一批文章，但永远有一个不安：是不是漏了某位关键学者在某年发表的那篇你忽略了、而评审恰好会问到的论文？

Deep Research 背后是 13 个 AI 智能体在协作。它们有明确分工：一个管研究架构，规划搜索策略；一个管文献目录，验证每一条引文是否真实存在；还有一个"风险偏倚"评估智能体，专门判断引用文献的方法论质量。

对人文社科尤其有用的，是它的系统综述模式（PRISMA 合规）和苏格拉底引导模式。

系统综述，很多社科的同学只听过概念但不知道怎么操作。ARS 帮你把流程规范化走完。苏格拉底模式更特别：它不给你答案，而是一轮一轮提问，帮你把研究问题逼问清楚。这套模式每 3 轮重新判断你的对话意图——你是在认真探索，还是已经有了答案只是在寻求确认——然后调整策略。每 5 轮还做一次对话健康度自检，防止AI一味迎合你，也防止你在还没想清楚时就过早收窄方向。

说白了，这个模块的前提是：你才是研究者，它是你的智囊团。不是它替你读，你坐等结论。

​

### 第二关：Academic Paper——12个智能体协同写作，你先写，它当编辑

写作模块有 10 种模式，对人文社科最实用的是这几种：

**修订教练模式**：你把审稿意见丢给它，它不帮你直接改，而是先把审稿人的批评转化成一份可执行的修改路线图。这个设计很聪明。直接让AI动手改，改出来的东西大概率失去你自己的声音。让它帮你理解"到底要改什么"，你自己动手，效果不一样。

**格式转换模式**：支持 APA、Chicago、MLA、IEEE、Vancouver 五种引文格式互相转换，还能把 Markdown 转成 LaTeX 再输出 PDF。论文最后一周调格式的痛苦，经历过的人都懂。

**引文核查模式**：接入了 Semantic Scholar 的 API，通过标题匹配和 DOI 比对来验证每一条引文是否真实存在。引文标注有三层：整段引用、分节引用，精确到句子和页数。最新版本还加了引用排放机制——先判引用形态，再标锚点，最后验证每条引文是否真的支持你引它的那段论述。不是"这篇文献存在"就完了，而是"你引它的那句话，它确实说了"。

**学科语言校准模式**：你喂给它过去写的 3 篇以上论文，它学习你的写作风格——句式节奏、用词偏好、引文融入习惯。然后在你写新文章时标记出那些"听起来不像你"的段落。AI写作最容易被识破的地方，不是内容好不好，而是"读着不对"。每个研究者都有自己的语言指纹，ARS 试图保护的就是这个。

​

### 第三关：Academic Paper Reviewer——投稿前先让"三个审稿人+一个魔鬼辩手"把你审一遍

这个功能模拟了一个完整的同行评审流程：一位主编统筹，三位审稿人各侧重不同维度，再加一个魔鬼辩手（Devil's Advocate）。0-100 分质量评估量规：≥80 接受，65-79 小修，50-64 大修，低于 50 拒稿。

魔鬼辩手的角色尤其关键。它挑战你的每一个论证弱点，而且不轻易妥协。你要反驳它，必须把你的反驳按 1-5 分打分，只有 ≥4 分它才让步。还不允许连续让步两次。

这解决的其实是一个AI的深层问题：谄媚偏差。AI天然倾向于说你想听的话。魔鬼辩手模式通过结构设计把这个倾向硬压了下去。

这对人文社科的意义：人文社科的论证往往比理工科更依赖修辞和解释，主观性更强。一个有真正挑战性的预审，能帮你发现那些你以为理所当然、但评审可能完全不吃那套的论证弱点。

​

### 第四关：Academic Pipeline——10个阶段串联，两道不可跳过的诚信闸门

这个模块把前面三个串成一条完整流水线：

研究 → 诚信闸1（不可跳过）→ 写作 → 诚信闸2（不可跳过）→ 评审 → 修订 → 再评审 → 定稿 → 流程总结

两个诚信闸门是强制的，你不能关。闸门处系统会跑一套合规检查清单——PRISMA-trAIce 17 项加上 RAISE 4 条原则——检测你的论文里有没有杜撰引文、统计错误、逻辑断层。

这个设计建在一个非常诚实的认知之上：你以为你查过了，大概率还是有漏的。

项目文档里有一个数据：展示案例做了出版后审计，经历了三轮诚信检查之后，68 条引文里仍然有 21 条存在问题。31% 的错误率。

纯靠 AI 不行，纯靠人也不行。真正的安全机制，是人和 AI 多轮交替检查。

## 这套系统的理论地基，比你想的扎实

一般的 AI 论文工具，开发者往往是纯工程背景。但 ARS 的设计文档引用了三篇关键研究来支撑架构决策：

Lu et al.（2026，Nature）对全自动 AI 研究系统的失败模式分析。第一个端到端的 AI 研究系统在 ICLR 2025 工作坊盲审中只得了 6.33/10 分，失败模式包括实现错误、幻觉实验结果、投机取巧特征依赖。ARS 把这些失败模式直接转化成了 7 项阻断检查，嵌入到流水线节点。

Zhao et al.（2026）对 AI 幻觉引文的系统性审计。2025 年一年间，250 万篇论文中估计出现了 146,932 条杜撰引文。更让人警惕的是：从预印本到正式出版，这些幻觉引文的留存率高达 85.3%。即使经过了同行评审和编辑校对，大多数杜撰引文照样蒙混过关。ARS 的引文验证层就是对这件事的直接回应。

Google 的 PaperOrchestra 系统，在语义学者验证、反泄露、视觉图形验证、评分轨迹追踪等方面的探索成果。

读这些引用文献，你会意识到 ARS 不是一个程序员拍脑袋做的工具。它的设计扎根于正在发生的学术讨论——关于 AI 在学术中的边界、危险，以及人机之间应该维持什么样的关系。

## 但说实话，这个项目对人文社科的用户并不友好

上面说了这么多，你可能已经心动了。但我要在这里踩一脚刹车。

ARS 是目前把"人机协作学术写作"这件事想得最透彻的开源项目，没有之一。但它的使用门槛，对人文社科背景的研究者来说，相当不友好。

它不是那种你打开浏览器、注册账号就能用的 SaaS 产品。它需要你：

**第一，安装 Claude Code。** Claude Code 是 Anthropic 推出的终端 AI 编程助手，运行在命令行里。你需要先在自己的电脑上装好 Node.js 和 npm，然后通过 npm 全局安装 Claude Code。这对于写过代码的人来说不算什么，但如果你的日常工作环境就是 Word 和浏览器，这一步就是第一道坎。

**第二，配置 API 密钥和账单。** 你需要注册 Anthropic 账号，申请 API 访问权限，拿到一串密钥（ANTHROPIC\_API\_KEY），在终端里配成环境变量。还要绑定信用卡或设置预付费额度。技术文档是全英文的。

**第三，安装插件和依赖。** 在 Claude Code 里通过 `/plugin marketplace add` 命令安装 ARS 插件。如果你想输出 PDF，还得额外装 Pandoc 和 tectonic（一个 LaTeX 引擎），以及中文字体（Source Han Serif TC）。这些东西说起来不难，但对于习惯图形界面的用户，终端里的每一步出错提示都让人摸不着头脑。

**第四，日常使用全靠命令行交互。** 你用 ARS 的方式，是在终端里敲 `/ars-research`、`/ars-write` 之类的斜杠命令。没有图形界面，没有按钮，一切靠键盘。这对习惯了点点鼠标就能完成操作的人文社科用户来说，学习曲线非常陡。

说白了，这个项目从设计到文档、从安装到使用，整个生态是为有编程背景的用户——主要是理工科研究者——准备的。一个做计算机的博士生可能半小时就配置好了。一个做文学或历史的博士生，可能折腾一个下午还没跑到第一步。

## 所以我打算做一件事

ARS 的功能本身，对人文社科研究者的价值是巨大的——甚至比对理工科更有价值。因为人文社科的写作更依赖论证的严密性和文献的真实性，而这些恰恰是 ARS 最擅长守住的底线。

问题不在工具。在门槛。

如果你对这个项目感兴趣，但被上面这些配置吓退了，可以联系我。我打算专门出一套面向人文社科用户、零编程基础的 ARS 配置和使用教程——从 Claude Code 安装、API 配置、插件加载，到第一个研究任务的完整执行，每一步都用截图和中文说明讲清楚。

我不卖课，也不收费。纯因为看到太多人文社科的朋友被工具门槛挡在了外面，而他们本应是最能从这套系统中受益的人。

## 最后

你读到这里可能会想：费这么大劲搞配置，值得吗？

我想说的是，ARS 这类工具本质上不是在降低学术写作的门槛。它降低的从来不是思考的门槛，而是那些消耗你精力、消磨你耐心、却跟你的学术能力无关的重复性劳动——找文献、排格式、验证引用、检查格式一致性。

这些事你做得好，不代表你是更好的学者。做不好，也不代表你不行。它们只是学术流水线上的苦工。ARS 做的，就是把这些苦工接过去。

但定义问题、选择方法、阐释数据、构建论证——这些真正需要判断力和创造力的部分，它完完整整留给了你。

而且，通过那两道不可跳过的诚信闸门、魔鬼辩手的质问、引文的三层验证，这个系统在不断提醒你一件事：

这篇论文的最终责任人，是你。

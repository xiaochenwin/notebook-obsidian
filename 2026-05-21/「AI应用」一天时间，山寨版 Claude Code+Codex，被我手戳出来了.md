一个人，一台电脑，一周时间，从零手搓了一个国产多模型AI编程桌面应用。中文界面，支持6大模型，编程模式、多模型对比、智能编排全都有。

![](https://relay-1.bijitongbu.site/p/7f8c54eec89b3b4d93423c3ebdaf9107.png)

自 Anthropic 发了 Claude Code，OpenAI 发布Codex，都是那种能在终端里帮你写代码的 AI Agent。

我已经用了几个月了，确实牛。

但我又看了看，嗯，有个问题。

这俩东西，都是英文界面，都是命令行操作，都得会点技术才能玩得转。你要是不会用终端，不会敲命令，那基本跟你没关系。

然后我就想，国外的套壳+国内的大模型一起玩DeepSeek、通义千问、智谱、Kimi、讯飞星火，这些模型单独拿出来，有的也能写代码，有的也能对话。但是我要记很多API，非常麻烦，Claude Code 那样的桌面应用，也可以分享给队友用，最重要的是把自己专业垂直领域的工作流都整合进去,未来私有化自己的数字资产。

于是，那我就做一个。

我要做个啥?

我的想法很简单，做一个桌面应用，打开就能用，不用敲命令行，中文界面，支持国内主流大模型。

然后把 Claude Code 和 Codex 那些核心能力搬过来。

多模型调用、流式对话、编程模式、文件操作、Git 管理、终端执行，这些东西，我全都要。

![](https://relay-1.bijitongbu.site/p/568ed763105b65a5622578570671ef55.png)

你可能觉得，这不是扯吗，一个人怎么做这种东西？

说实话，我自己一开始也觉得有点扯。

但你知道的，人一旦上了头，就很难停下来。

​

从零开始的第一天

​

我打开deepseek的网页版一起探讨claude code 指令(主要在于deepseek做内容这块非常擅长，我主要用来帮助我理清思路然后用promote表达出来，将deepseek输出的表达，复制给小米MIMO的网页版，帮我理清claude code的工程架构(小米MIMO对比ds来说,更懂claude code的工程设计)，claude.md的初稿是由deepseek和小米MIMO一起合作输出的，至于最终决定用什么，我将claude.md在claude code中运行,让其自行完善和进化技术栈

我到底该用什么技术栈？

Electron 做桌面应用，这个没争议，跨平台，JS 生态丰富。但前端用什么？React 还是 Vue？状态管理用什么？构建工具用什么？

想了半天，我决定用 React + TypeScript + Zustand + Vite。

为什么选 Zustand 不选 Redux？因为我懒。Zustand 的 API 太简洁了，一个 \`create\` 搞定，不用写 action、reducer、dispatch 那一套。我一个人写项目，不需要那么重的东西。

就这样，项目开始了。

​

流式输出，最折磨人的部分

![](https://relay-1.bijitongbu.site/p/bdc89d1c67935d34f14fdee6c984d391.png)

![](https://relay-1.bijitongbu.site/p/f2d83ae0d9baa86558bee304803310fe.png)

接下来是流式输出。

你知道什么是流式输出吗？就是 AI 不是等全部生成完了一次性给你，而是一个字一个字往外蹦。ChatGPT 那种打字机效果，就是流式输出。

这个东西实现起来，比你想的要复杂得多。

因为你要处理的不只是「文字一个一个出来」这么简单。你还要处理：

用户等不及了，想停止。你得把正在跑的进程杀掉。

用户同时开好几个对话，每个对话的流式数据不能混在一起。你得用 requestId 隔离。

网络断了，进程崩了，你得有错误处理。

中间用户又发了一条新消息，你得判断是继续当前对话还是开新的。

这些东西，文档上都不会写。你只能自己踩坑，自己爬出来。

我在这个地方卡了N次，好在一天能收工。

​

编程模式，最爽的部分

![](https://relay-1.bijitongbu.site/p/9c0d27a7bc9e6f0531599c8a8eaee881.png)

做完基础对话之后，我开始搞编程模式。

这个部分是整个项目里我做得最爽的。

因为编程模式的核心就是，让 AI 能读你的代码、改你的代码、帮你跑命令。

实现起来，就是在 Electron 主进程里加一堆 IPC 通道。读文件、写文件、列目录、执行命令、Git 操作，每个功能一个通道。

安全问题是个大坑。你不能让用户通过 AI 把系统文件给删了，也不能让 AI 执行个 \`rm -rf /\` 把整个电脑给清了。

所以我加了一堆限制。

文件读写限制 1MB。路径越界检查，确保操作的文件在项目目录内。终端命令 30s 超时。Git 文件路径用 JSON.stringify 转义，防命令注入。

这些安全措施，看着都是小事，少做一个可能就炸了。

比较骚的是 Git 操作这块。我一开始用的是 fire-and-forget 的方式，就是发完命令不等结果。后来发现这会有竞态条件，两个 Git 操作同时跑，结果互相覆盖。

改成 async/await 之后就好了。

这个坑我踩了才知道。

模板商店，最意外的收获

![](https://relay-1.bijitongbu.site/p/41ade3cb53127c837e439593221ba506.png)

![](https://relay-1.bijitongbu.site/p/01ad58cc56711c57cc365196b0b9a437.png)

做完编程模式之后，有一天我在想一个问题。

AI 能帮我写代码，能帮我改代码，但是我想把所有喜欢的html模版放在自己的智能体里面，未来做幻灯片直接取用。顺着这个思路，我做了一个模板商店。

就是那种卡片式的界面，每个模板一张预览图，点进去能看到详情、适用场景、风格标签，然后一键「使用模板创建」，直接跳到对话界面，AI 已经知道你要什么风格了。

​

做出来之后我发现，这个功能比我想象的有用。

​

以前做幻灯片，要么自己从零开始，丑得一批。要么花钱买模板，买了也不会改。

现在呢，选一个模板，跟 AI 说「帮我做一个关于 Q2 业务汇报的幻灯片」，它就照着模板的风格给你生成。你再微调一下文字，非常快搞定。

这块需要注意一下，模板的核心价值不是模板本身，而是它给了 AI 一个「视觉锚点」。有了锚点，AI 的输出质量会上一个台阶。没有锚点，它就是在瞎画。

​

子 Agent 编排，最疯狂的部分

​

做完编程模式之后，我开始想一个更大的事情。

能不能让多个模型一起干活？

就像一个项目经理，手底下有几个程序员，每个人擅长不同的东西。项目经理负责拆解任务、分配任务、最后汇总结果。

我给它起了个名字，叫「智能编排」。

实现思路是这样的，用户发一个问题过来，先用 Claude 来做规划，把问题拆解成几个子任务。然后把子任务分发给不同的模型并行执行。最后再用一个模型来汇总所有结果。

三阶段管线，规划→执行→汇总。

这个东西还比较粗糙，后续可以继续完善功能了。

### 电子宠物，最没用但最让人开心的功能

![](https://relay-1.bijitongbu.site/p/cf04711e1483bc563cd44cdf4b911c3c.png)

![](https://relay-1.bijitongbu.site/p/de3e3da264626e8f6817ee0d7e84f3ee.png)

做完上面那些之后，我突然想加个电子宠物。

就是那种会摇尾巴、会眨眼、你摸它头它会开心的小狗。

用纯 CSS 画的，没有用任何图片。耳朵是椭圆，脸是圆形，眼睛里有高光点，舌头会伸出来，尾巴会摇。

颜色用的是品牌色。

它会自动冒出一些气泡，上面写着「加油」「代码一次过」「Bug消失」「今天不加班」这种话。

这个功能有什么用吗？

没用。

一点用都没有。

但我就是觉得，写代码的时候，屏幕右下角有个小东西陪着你，偶尔给你冒个气泡说「加油」，那种感觉，就是情绪价值，还挺好的。

有时候你盯着一个 Bug 看了半小时，一抬头，看到它在那摇尾巴。

就，没那么孤独了。

​

### 未来推演

基于纵向趋势和横向竞争格局，给出三个剧本：

## 剧本一：最可能的——小众工具，自用为主

这个产品继续作为个人项目存在，功能逐步完善，但用户规模始终有限。它不会成为一个商业产品，但会成为作者日常工作中不可或缺的工具。偶尔有朋友看到，会说「这个挺好的，给我也装一个」。

## 剧本二：最危险的——被大厂碾压

某个大厂（比如字节、阿里、百度）推出了许多的国产多模型桌面应用，有团队、有资源、有渠道。这个产品在功能上本身被全面超越，在体验上被碾压，在品牌上完全无法竞争。

## 剧本三：最乐观的——成为种子，长成大树

产品的核心理念（多模型、中文原生、零门槛）被验证是正确的方向。找到志同道合的伙伴，组建小团队，把产品打磨得更好。在国产AI工具这个细分赛道里，聚焦专业垂直领域，找到自己的位置。

​

### 一个更深层的判断

目前，这个产品真正的价值，不在于它本身有多好，而在于它证明了一件事。

一个普通人，用现有的开源工具和国产大模型，也能做出一个还不错的AI编程助手。不需要几亿美元，不需要几百人的团队。只需要一台电脑、一点编程基础、和一股上了头的劲儿。

Claude Code和Codex代表的是「精英路线」，最好的团队、最多的资源、最强的模型。牛雪梨AI表的是「平民路线」，现有的工具、普通的资源、够用的模型。

两条路线都有价值。精英路线推动技术前沿，平民路线扩大技术普惠和垂直应用。

在AI时代，这两条路线的差距会越来越大还是越来越小？

我觉得会越来越小。

因为模型在变强，工具在变好，门槛在降低。今天需要一周才能做出来的东西，明天可能一天就够了。

这才是真正让人兴奋的事情。

# 今日分享

> 告别「复制 → Clipper → 事后整理」的老路子，现在只需把链接丢给 Trae Solo，剩下的全自动搞定。

---

## 一、痛点：知识库整理的「最后一公里」

你有没有这样的经历？

刷公众号看到一篇好文章，赶紧用 Obsidian Web Clipper 剪藏到收集箱。然后...就没有然后了。

收集箱里的文章越堆越多，标签没打、来源没填、知识没提炼。等到想整理的时候，已经攒了几十篇，看着就头大。

**传统的知识管理流程是这样的：**

​

```
看到好内容 → 复制/Clipper剪藏 → 存入收集箱 → （拖延）→ 事后集中整理 → 累了放弃
```

问题出在哪？

1.  1\. **收集和整理分离**：收集时爽，整理时痛苦
    
2.  2\. **信息孤岛**：原始内容和提炼后的知识没有自动关联
    
3.  3\. **重复劳动**：每次整理都要手动提取标签、来源、摘要
    

我一直在想：能不能把「整理」这个动作前置，让 AI 在收集的同时就完成整理？

​

---

## 二、新思路：让 Trae Solo 成为你的「知识整理员」

Trae Solo 是一个支持自定义 Skill 的 AI 助手。它的强大之处在于：**你可以用自然语言描述需求，它会自动帮你执行复杂的工作流。**

我的想法是：

> 与其把内容存到 Obsidian 再整理，不如直接把链接丢给 Trae Solo，让它按照我定义的规则，自动完成「收集 + 整理 + 归档」全流程。

**新的知识管理流程：**

​

```
看到好内容 → 把链接发给 Trae Solo → 自动完成：
  ├─ 抓取网页内容
  ├─ 提取标题、标签、来源
  ├─ 生成原始信息归档笔记
  ├─ 提炼知识要点
  ├─ 自动归类到领域文件夹
  └─ 建立双向链接
```

**效率对比：**

​

| 传统方式 | 新方式 |
| :-- | :-- |
| 手动剪藏 → 事后整理 | 发链接 → 自动完成 |
| 整理一篇需要 5-10 分钟 | 全程 0 手动操作 |
| 容易拖延、堆积 | 即时处理、不积压 |
| 信息孤岛 | 自动建立知识关联 |

## 三、手搓 Skill：从需求到实现

### 3.1 明确需求

我需要的 Skill 要能处理这些输入：

-   • 🔗 链接（公众号文章、博客、网页）
    
-   • 📝 纯文字（复制粘贴的内容）
    
-   • 🖼️ 图片（截图、照片）
    
-   • 📄 文件（PDF、Excel、PPT、Word、TXT）
    

输出要分两层：

1.  1\. **原始信息归档**：完整保存输入内容，按模板格式存入收集箱
    
2.  2\. **知识提炼**：提取核心要点，自动归类到领域文件夹，建立双向链接
    

### 3.2 设计知识库结构

我的 Obsidian 知识库采用「PARA + 领域」的混合结构：

​

```
E:\BaiduSyncdisk\Obsidian知识库\
│
├── Ai辅助学习/                    ← 通用知识
│   ├── 02-收集箱/                 ← 原始信息入口
│   ├── 04-领域/                   ← 知识提炼输出
│   └── 07-资源/                   ← 图片保存
│
├── Ansys Workbench学习/           ← 专业领域
├── Creo学习/                      ← 专业领域
└── 学习方法/                      ← 方法论
```

### 3.3 编写 SKILL.md

Trae Solo 的 Skill 本质上是一个 Markdown 文件，用自然语言告诉 AI 该怎么干活。

**核心结构：**

​

```
---
name: obsidian-knowledge-organizer
description: |
  自动整理 Obsidian 知识库的 Skill。
  触发关键词：整理知识库、收集信息、知识提炼、归档笔记
---
```

**关键内容包括：**

1.  1\. **知识库路径与结构**：告诉 AI 你的文件夹在哪、每个文件夹存什么
    
2.  2\. **输入类型处理**：链接用 WebFetch 抓取、文件用对应工具提取
    
3.  3\. **分类路由规则**：Ansys 相关放 Ansys 文件夹、Creo 相关放 Creo 文件夹
    
4.  4\. **输出模板**：原始归档用什么格式、知识提炼用什么格式
    
5.  5\. **命名规范**：文件名、图片名的命名规则
    

### 3.4 完整的 Skill 文件

最终我搓出来的 Skill 包含以下核心模块：

​

| 模块 | 功能 |
| :-- | :-- |
| 知识库结构定义 | 完整的文件夹树和路径说明 |
| 输入类型处理 | 链接/文字/图片/文件的处理方式 |
| 图片命名规范 | `YYYYMMDD-HHMMSS_来源_描述.扩展名` |
| 内容分类路由 | Ansys/Creo/学习方法/通用 四大模块 |
| 原始信息归档模板 | 信息收集模板格式 |
| 知识提炼模板 | 领域笔记格式 + 去重合并规则 |
| 双向链接规则 | 原始笔记 ↔ 领域笔记自动关联 |

## 四、实际效果演示

### 场景一：整理一篇公众号文章

**输入：**

​

```
整理知识库：https://mp.weixin.qq.com/s/xxxxx
```

**Trae Solo 自动完成：**

1.  1\. 抓取文章内容，提取标题、作者、发布时间
    
2.  2\. 生成原始归档笔记，存入 `02-收集箱/`
    
3.  3\. 分析内容主题，判断属于哪个领域
    
4.  4\. 提炼知识要点，存入 `04-领域/` 对应文件
    
5.  5\. 在两个笔记之间建立 `[[双向链接]]`
    

### 场景二：整理一个 PDF 文件

**输入：**

​

```
整理知识库，文件：有限元分析教程.pdf
```

**Trae Solo 自动完成：**

1.  1\. 提取 PDF 文本内容
    
2.  2\. 识别为 Ansys 相关内容
    
3.  3\. 原始资料存入 `Ansys Workbench学习/05-参考资料/`
    
4.  4\. 知识要点提炼后存入 `02-模块学习/`
    
5.  5\. PDF 中的图片保存到 `07-资源/`，命名规范为 `20260517-143025_ansys_网格划分示例.png`

## 五、与传统方式的对比

| 维度 | 传统方式（Clipper + 事后整理） | Trae Solo Skill |
| :-- | :-- | :-- |
| **操作步骤** | 剪藏 → 打标签 → 填来源 → 提炼要点 → 归档 | 发链接 → 完成 |
| **时间成本** | 每篇 5-10 分钟 | 几乎为零 |
| **信息完整度** | 容易遗漏标签、来源 | 自动提取，不会遗漏 |
| **知识关联** | 手动建立链接 | 自动双向链接 |
| **重复内容** | 容易重复收集 | 自动去重合并 |
| **心理负担** | 看着收集箱就累 | 无负担，即收即整 |

## 六、如何开始？

### 步骤 1：准备 Skill 文件

在 Obsidian 的 Templates 文件夹下创建 `obsidian-knowledge-organizer/SKILL.md`。

### 步骤 2：复制到 Trae Solo

将整个文件夹复制到 Trae Solo 的 skills 目录：

​

```
c:\Users\你的用户名\.trae-cn\skills\
```

### 步骤 3：开始使用

在 Trae Solo 中说：

-   • 「整理知识库：\[链接\]」
    
-   • 「收集信息：\[文字内容\]」
    
-   • 「知识提炼：\[上传文件\]」

## 七、写在最后

这个 Skill 的核心价值不在于技术有多复杂，而在于**改变了知识管理的工作流**：

> 从「先收集、再整理」变成「收集即整理」。

以前我总是拖延整理收集箱，现在只需要把链接丢给 Trae Solo，剩下的全自动完成。知识库不再是「漂亮的废纸堆」，而是真正在生长的知识网络。

如果你也在用 Trae Solo 和 Obsidian，不妨试试这个思路。**让 AI 帮你干脏活累活，你只需要专注于「输入」和「输出」。**
